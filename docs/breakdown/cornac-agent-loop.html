One loop, four layers underneath it, and two Week-3 guards slotted in without changing its shape. This is the whole of ankus (code currently cornac; rename in progress).

The loop, with the Week-3 gate in place

Every feature of the harness is a stop on this circuit. Follow a user message clockwise: the model either answers (exit) or orders tools — and every order passes the hook and permission checkpoints before it runs.

The four layers under the loop

The loop stays ~15 lines because every hard thing is pushed down into a single-purpose module. Weeks 1–2 built the amber layers; Week 3 added the blue ones.

1 · Messages

core/messages.py

The shared vocabulary. A conversation is a growing list[Message] — the agent’s only memory. ToolCall is the order ticket, ToolResult the plate that comes back.

2 · Tools + Registry

tools/

Nine tools behind one 4-part contract (name · description · schema · run). The registry dispatches by name and turns every failure into an error result — never a crash.

3 · Providers

providers/

The firewall. Anthropic and Ollama adapters translate neutral ↔ native at the edge, so swapping Claude for a local Qwen changes one line.

4 · The Loop

core/agent.py

Ask → done? → run tools → feed results back → ask again. The wants_tools check is the hinge; max_steps is the rail.

5 · Permissions

permissions/

The rulebook (ALLOW/DENY/ASK) plus a swappable human approver. The real gate for arbitrary-code tools the sandbox can’t fence.

6 · Hooks

hooks/bus.py

Publish/subscribe events at fixed loop points. Observers watch without copying the loop; a broken hook can never take the agent down.

One request, traced

“What time is it in Tokyo?” — watch the memory grow. Two model turns, stitched together by feeding the tool result back.

  • system“You are a concise assistant…” — seeded at construction
  • user“What is the current time in Tokyo?”
  • assistant(no text) → get_current_time({timezone: "Asia/Tokyo"}) — an order, not an answer
  • tool“2026-07-14 21:04:50 JST” — the plate, appended so the model sees it
  • assistant“It’s 9:04 PM in Tokyo.” — no tool calls → loop returns ✅

The permission ladder

Four checks in priority order — first match wins. Deny patterns are tested before allow patterns, so sudo pytest can’t sneak through on the strength of pytest.

#CheckExampleVerdict
1Session override — an earlier “always / never” answer you pressed a for run_pythonALLOW
2Tool not listed in the rules at all some_new_toolASK
3Simple rule — plain verdict per tool read_file (read-only)ALLOW
4Rich rule — deny list first, then allow list, then default run_bash("sudo pytest")DENY
The thesis, in one loop: a weak 7-billion-parameter model on a laptop GPU planned multi-step work, recovered from its own errors, and respected human permission gates — not because the model got smarter, but because the scaffolding around it did. Capability lives in the harness.
